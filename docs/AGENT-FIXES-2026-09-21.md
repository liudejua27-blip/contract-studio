# Agent 可靠性修复记录

本轮修复事实提取、律师事项跨轮保存、场景追问和无初稿咨询。沿用 Pi Agent Core，不引入另一套 Agent 运行时。

## 已实现

- 提取事实只能使用对应完整证据原文或多段原文拼接（不截掉否定和条件）。模型增加的“终身免费维护”等义务不再直接写进事实。已有数值校验保留。这约束的是证据边界，不等于保证模型把证据放对字段或理解完全正确。
- 律师待审事项跨轮合并保留，包括切换合同类型。当前采用保守保留，不自动关闭旧事项，由律师结合对话核对。
- 仅有一个建议时，自然语言接受限制为明确、独立的肯定回复，避免“可以不按建议”被当成采纳。
- 软件运维、采购安装调试、宣传视频用途加入条件问题。仅提到“需要安装”或“需要维护”不能视为该安排完整。每轮仍最多三问。未定的场景安排转成律师关注事项；未知金额等核心事实仍不编造。
- 尚无初稿时可提交已有需求咨询。保留原始对话、交易摘要、未定事项、律师关注事项；律师可沟通、上传起草后的 Word、确认交付。没有虚构合同版本，也没有绕过文件上传和确认交付检查。
- 客户、律师、管理员权限和送审冻结沿用原流程。Cloudflare 的合同 JSON 存储无需迁移。PostgreSQL 需要运行项目现有初始化/迁移入口，使 `reviews.submitted_version_id` 可为空；外键约束保留。在线编辑器需先有文件。

## 验证

- Pi 专项回归包含非数字义务注入、律师事项保存、场景追问和未定事项不重复追问。
- Worker 回归新增无初稿咨询：跨客户隔离、律师接收、双方沟通、上传、交付闭环通过。
- Chrome 手机视口实际操作“请律师帮我完善需求”、填写提交信息、进入无文档咨询页通过。
- `scripts/evaluate-agent.ts` 使用三个合成业务场景调用真实 DeepSeek。最终三个场景均问出一项相关问题，提取结果均满足证据原文边界。首次运行暴露了“仅提到安装/维护就当作完整”的问题，修复后复测通过。
- 这些不是实际客户样本；没有真人律师审稿，律师修改量为 null，不能宣称法律质量通过或事实错误率为零。报告写入忽略的 `.data/agent-evaluation.json`。

## 后续限制

按用户最新要求，仅使用 Sites。可选 Queue 代码与配置已删除，不再要求独立 Cloudflare 环境。页面逐阶段推进任务，保留刷新恢复、取消和重试；关闭页面后不保证继续生成。

真实客户案例和律师修改量需要后续实际使用的数据。采集时使用经授权脱敏案例，按同一案例记录追问轮数、错误事实、律师实质修改项和最终交付结果。当前不自动上传私人合同到外部评测服务。
