# 合同 Agent 第一轮升级

范围：统一业务规则来源、清理重复提示和旧追问，贯通核心诉求与立场。本次是本地实现及验证，未部署，也未扩展材料读取、法律检索或复杂交易关系模型。

## 规则来源与职责

| 内容 | 唯一维护入口 | 使用方式 |
| --- | --- | --- |
| 交易理解、事实、意图、追问、起草判断 | `skills/transaction-contract/SKILL.md`（5.1.0） | 各模型阶段加载；专项资料只作补充 |
| Word 表达、主体字段、表格与附件 | `skills/contract-word/SKILL.md`（3.2.0） | 起草、修改、核验加载 |
| 阶段任务和工具操作说明 | `src/server/agent/prompt.ts` | 理解、起草、局部修改、核验分别指定任务，不再重写整套业务规则 |
| 普通专业条款正文 | `src/lib/standard-terms.ts` | 需求理解可读取，当前选用条款通过交易摘要传给后续阶段 |
| 通用缺口问法 | `src/lib/contract-questions.ts` | 规则包、旧问题入口、主流程共用；是缺口问法，不是必填问卷 |
| 结构、来源和完整性检查 | 对应 Schema、交易编译器和文档校验器 | 保留确定性检查，不以减少提示词为由取消证据、权限和文件完整性约束 |

`legal-skills.generated.json` 是生成产物。启动开发服务及构建网站前自动更新，测试会检查它与平台 Skill 原文一致。平台 Skill 版本从原文读取，避免源文档和回执版本分别手工维护。

阶段路由改为显式参数，不再从提示词文本中搜索阶段标记决定工具与 Schema，避免用户目标中的同名文字干扰路由。

## 核心诉求与立场

`Intake.intent` 分别保存 `goal` 和 `stance`，每项有概括值与用户原话。它们与双方已约定的 `facts` 分开，不成为新的起草必填项。

- 对话里明确表达后记录；未变化时沿用，更正只覆盖对应项目。
- 更正和撤回必须引用本轮用户原话。撤回保留空值及撤回证据，防止旧目标在之后的对话中重新出现。
- 起草、局部修改、核验读取当前意图。诉求里的赔偿金额不会因此成为合同可采用的已确认金额。
- 交易摘要显示起草方向，允许用户在对话中更正。
- 生成版本保存当时的意图快照。送审弹窗从所选版本预填，可补充；咨询协助从当前交易记录预填。没有意图记录的旧版本不会借用新版本的目标。
- 送审时修改说明保存在审核记录，不会暗中改写已生成 Word 或冻结版本。

## 减少重复问题

所有平台规则包和兜底问法中的主体问题统一为角色与职责，名称可以留空。已识别的无名参与方不会被旧记录中的名称缺项重新阻塞。

真实模型小样本发现：旧兼容转换会把一条普通违约建议自动转成缺项，虽然模型已经选择采用普通违约规则。现已明确：新协议由 `businessChecks` 统一判断缺项，建议不自动产生另一套生成门槛。仅完全没有 `businessChecks` 的旧格式，在输入边界保留兼容转换；现有历史合同及旧测试协议仍可读取。
