# 第二轮：交易关系、条款关联与连续修改

范围：现有 Node + Pi Agent 链路；没有迁移框架、恢复 Sites 或增加模型调用阶段。

## 交付行为

- 交易理解工具增加可选增量关系：稳定 ID、履行方、接受方、行为、原话来源、履行条件和前置关系。多方可以名称留空，角色分别保留；关系整理不新增用户必答问题。
- 当前事实仍是权威依据。关系必须引用存在的主体和事实，并定位事实原话；撤回需要本轮原话。依据被更正或角色改变时，相关旧关系及失去前置依据的关系失效，交给 Agent 内部重新理解，不自动变成追问。
- 起草工具可申报事实/关系到正文及附件的关联，平台核对实际句子和索引，将关联绑定到正文指纹。关联是模型解释的可定位记录，不代表法律正确性或事实覆盖证明。
- 局部修改前，平台比较两版事实、关系、主体和意图，沿前置/后续关系查找相关正文与附件。计划提供候选位置；模型可按实际需要保留或修改，也可修改候选之外的位置。
- 修改后保留无关正文，删除/合并条款时重新计算未修改关联的位置；变更条款及失效事实的旧关联不继续继承。新版本保存修改原因、原位置/结果位置、候选实际处理结果，供一致性核验及下一轮使用。
- 用户本次修改原话随后台任务保存，确认和自动修复不再把具体修改要求替换成通用指令。最长保留近期 32,000 字，较早内容继续通过原始对话工具读取。
- 旧稿无关联、关联指纹过期、事实没有落点、主体或意图变化等情况回退全文检查；完整一致性核验仍然执行，不能凭计划覆盖率直接导出。

## 规则和实现位置

业务判断统一在 `skills/transaction-contract/SKILL.md` 5.2.0；生成的规则包同步更新。没有新增独立 Skill 或模型工具。

| 内容 | 位置 |
| --- | --- |
| 关系结构、引用校验、更新和失效处理 | `src/lib/transaction-relations.ts` |
| 条款关联、影响计划、位置迁移和修改记录 | `src/lib/contract-impact.ts` |
| 理解结果写入 | `src/lib/transaction-update.ts` |

数据保存在现有交易/版本 JSON 中；新增字段可选，旧数据可继续使用，无需 SQL 数据迁移。关联和计划不写进 Word 正文，也不出现在公开生成文本流中。

- Node 正式构建及独立 worker 构建通过。记录 `.data/qa/phase2-build.log`。
- 发布产物后台流程检查通过：使用临时数据库和本地模型/存储替身，3 次替身调用，关系及条款关联经过 worker 和 JSONB 版本持久化，并完成送审、上传及交付流程。结果记录 `.data/qa/phase2-server.log`。

本轮没有付费模型调用、100 用户压力测试、部署或律师专业验收。自动测试通过率不是实际模型生成成功率；95% 的模型评测目标未改变，也未在本轮重新测定。关系和条款关联仍依赖模型正确理解原话；跨条款语义完整性继续由一致性核验和律师审查承担。当前变更没有建立独立的多币种/多付款流算账引擎。
