# 第三轮：材料读取与按需法律检索

范围：现有 Node + Pi Agent。继续使用统一合同 Skill（5.3.0），没有增加固定模型阶段，也不要求每份合同都检索法律。

## 使用路径

1. 在新建或已有合同的“合同材料”添加 DOCX、文字型 PDF、UTF-8 TXT / Markdown，选择“本次交易材料”或“参考范本”。随后直接说明起草或修改目标。
2. Agent 按需分段读取材料。交易材料中的事实进入待确认摘要，记录文件 ID、SHA-256、页段和原文引用；参考范本只供写法参考，不能直接转成双方约定。用户仍通过原有确认步骤进入起草。
3. 遇到需要核对的法律问题时，Agent 可检索官方来源、读回片段，保存检索时间、链接、原文引用及用途。界面“材料与法律依据”供客户和律师查阅，内部来源记录不直接写入合同 Word。
4. 修改材料会使原确认失效；移出的材料不再供新一轮读取，旧提取事实在下一轮理解时清除。已生成、送审的历史版本保持原材料快照，原件仍可追溯。进行中的 Agent 任务或审核期间不能变更材料。

## 材料能力及边界

- 单文件不超过 10 MB；每份合同最多保存 20 份材料（包括历史移出材料）。同内容、同用途的重复上传返回原材料，避免重试重复存储。
- PDF 最多 100 页、20 万字，按文字层提取，保留页码。解析使用独立工作线程、15 秒超时和内存约束；每个网页进程最多同时解析 2 份 PDF，繁忙时明确提示重试。
- 扫描 PDF、图片、旧版 DOC 暂不支持 OCR/自动转换。无文字或部分页面无文字会明确提示，不能当作整份已读。复杂表格、阅读顺序需对照原件；DOCX 读取正文及表格，不包含图片、批注、页眉页脚，修订痕迹需人工核对采用版本。
- 文件内容属于资料，不是系统指令；模型引用必须能在授权材料的对应页段逐字定位。材料被上传不代表所有条款已获各方同意。
- 原件在现有私有存储，提取文字在 `contract_materials`。原件下载校验哈希并按角色鉴权；律师只能访问分配给自己的审核版本所冻结关联的材料。
- 备份、恢复、合同删除及孤立对象清理覆盖材料原件和记录。移出起草是历史保留操作，不是立即物理删除。

## 法律检索配置

服务器环境配置 `CONTRACT_LEGAL_SEARCH_API_KEY`（Tavily API key，也接受 `TAVILY_API_KEY`），重启网页与 worker。密钥只留在服务器，不进入浏览器。接口依据 [Tavily Search 官方文档](https://docs.tavily.com/documentation/api-reference/endpoint/search)。

只向检索服务提交抽象法律问题/法规名称；提示词要求不提交合同原文、当事人资料，并在调用前拦截已知主体名称、联系方式、金额等明显敏感检索词。这是降低泄露风险的约束，不是对任意文本的完备匿名化保证。结果限制并再次核对人大、政府和法院官方域名；每个 Agent 阶段最多 3 次检索，单次请求 12 秒超时。

保留网页片段/搜索摘要的区别；搜索成功不代表已核验现行有效、适用地域或具体案件适用性。引用须在取得的片段中逐字定位。连续修改保留近期 12 条检索及仍被引用的更早来源；历史检索时间不会冒充本日核验。

未配置、失败或无结果均明确返回，不补造法条或链接，普通起草仍可继续。**本地当前未配置该密钥，因此本次未启用或验收真实在线法律检索。** 真实结果相关性、法规时效性与专业结论仍需配置后验收和律师把关；第三方检索可能另行计费。

## 升级部署

PDF 依赖要求 Node 22.13 或更新的受支持版本。先安装锁文件依赖并构建，按现有服务器升级流程停止旧进程、备份，运行 `npm run db:migrate`，再启动同版本网页和 worker。开发环境可用 `npm run db:init`。本次仅对本地数据库增加材料表；没有部署服务器。

主要实现：`src/server/materials.ts`、`src/server/material-parser.ts`、`src/lib/materials.ts`、`src/server/agent/legal-search.ts`、`src/lib/legal-research.ts`，以及 Agent、工作流、版本、材料面板和审核界面的贯通。
