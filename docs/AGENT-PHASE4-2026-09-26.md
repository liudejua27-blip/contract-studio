# 第四轮：经确认的条款偏好与律师评估样本

本轮完成的是反馈积累机制，不是模型训练或质量提升证明。继续使用现有 Node + Pi SDK，统一合同 Skill 升至 5.4.0，没有新增固定模型阶段，也不会把所有律师修改拼进系统提示词。

## 网站使用

- 律师在已完成审核的“交付”页展开“整理一条律师反馈”。选择修改类型、摘取送审及交付原文、说明理由，再决定提议偏好、整理样本或两者兼有。新增或删除条款可留空一侧。原件哈希与逐字引用核对通过才会保存。
- 客户侧新增“我的条款偏好”。律师提议经本人确认后，才能用于自己的后续合同；管理员不能代替客户确认。偏好包含合同类型、立场、适用与例外情形。客户可拒绝或停用，不修改已有合同。
- 律师和管理员侧新增“反馈与质量积累”。匿名评估场景需律师重新编写，填写预期结果、逐项标准与开发/留出用途；管理员核对去标识及商业秘密后确认入库，可拒绝或撤回。
- 待确认反馈及处理结果进入现有站内消息。原始修改、理由、确认/撤回操作者及时间保留，来源文件仍按合同及审核权限访问。
- 单次协商安排不能直接变成可复用偏好。被客户要求继续修改的交付，其反馈自动暂停参与后续偏好匹配与样本导出。

## 起草如何复用

服务器只加载本客户已确认、匹配类型及立场的偏好，最多 12 条，按提案新到旧排列。当前实现类型按匹配专项、立场按非空文字相等筛选；不是跨客户共享库，也不做隐式立场推断。适用/例外情形由 Agent 结合本次交易判断。

通过 `get_clause_preferences` 按需读取；本轮事实和用户明确要求优先，不把偏好变成对方承诺或新增必答问题。起草与局部修改可提交采用/跳过原因，采用时必须引用当前正文。版本保存当时的候选快照和使用记录，一致性核验收到同一快照。没有使用记录时界面明确“供参考，未记录采用”，不把读取工具当作采用成功。

停用影响之后的新起草任务，已开始处理的稿件及旧版本仍保留当时快照；偏好变化进入运行缓存标识，历史工具结果不能代表本次仍有效。偏好之间没有自动冲突消解或法律效力认证。

## 评估如何积累

样本与生产起草上下文隔离；预期答案、判断标准、留出标签不发送给生成模型。导出只包含经人工确认的匿名场景与评估字段，不带客户 ID、合同 ID、原始摘录、Word 或沟通记录。身份筛查只是辅助规则，不能替代律师和管理员的匿名化判断。

同一审核来源不能同时进入开发集和留出集；去掉空白后相同场景不能重复计样本。语义近似场景和同一交易的跨轮审核仍需人工避免重复，当前没有语义去重服务。提案内容不可原地覆盖，拒绝或撤回后由律师按修正内容重新整理，保留旧记录。

本地维护命令：

```sh
# 导出当前已确认样本，无模型调用；目标文件必须不存在
npm run eval:feedback -- --export .data/qa/feedback/cases.json

# 显式调用模型生成条款，可能计费；本轮没有执行此项
npm run eval:feedback -- --generate .data/qa/feedback/cases.json .data/qa/feedback/run-1

# 人工填写 run-1/review.json 的评审人、逐项判断和理由后评分，无模型调用
npm run eval:feedback -- --score .data/qa/feedback/cases.json .data/qa/feedback/run-1/outputs.json .data/qa/feedback/run-1/review.json
```

生成前检查样本仍处于有效确认状态；撤回、来源待修改或确认记录变化时要求重新导出。导出与输出有指纹，评审绑定具体样本集及具体模型输出。记录模型名、提示和规则来源指纹、思考配置，支持同一匿名样本集跨版本复评。文件采用私有权限，禁止覆盖已有报告。

默认评估目标 95%，开发与留出分别统计。每条标准由评审人判断通过、失败或待判断；未评审、判断不全、生成失败、重复结果不能当作成功。未完成评审不能通过质量门槛。当前评估是**条款级**，不是整份合同专业审定、生产端到端验收或统计置信证明；小样本达到 95% 也不能据此推断真实总体成功率。

## 数据与部署

新增 `review_learning` 表保存来源、提案、确认状态及处理日志；客户/指定律师/管理员角色隔离。反馈与决策使用事务和版本号，拒绝旧页面覆盖新状态，创建请求支持幂等重试。

本地只添加了该表和索引；服务器升级仍需先备份、运行本版本 `db:migrate`，再启动同版网页与 worker。本轮未部署。数据库备份包含反馈记录；来源合同到期清理时级联删除。已导出的匿名样本集和旧评估报告是独立私有文件，需由运营方另行管理保留/删除，不能假定撤回已物理抹除旧文件。

- 249 项自动测试：244 通过、5 项按配置跳过，0 失败。新增 9 项覆盖反馈来源、条件匹配、使用引用、去标识筛查、样本指纹、人工评分边界及真实 Agent 工具链（模型替身）。记录 `.data/qa/phase4-tests.log`。
- 类型检查、Node 网页与后台构建通过。记录 `.data/qa/phase4-types.log`、`.data/qa/phase4-build.log`。
- 构建产物与独立 worker 流程检查覆盖律师反馈、客户确认、管理员确认、重复请求、旧版本拒绝、下一份合同采用与不同客户隔离、停用与历史快照。仅调用本地模型替身。记录 `.data/qa/phase4-server.log`。
- PostgreSQL 17 备份恢复及合同删除检查覆盖反馈表。记录 `.data/qa/phase4-backup.log`。
- 隔离浏览器账户完成律师提交反馈、客户确认偏好、管理员核对后确认样本，检查来源和历史处理记录。临时合同、账户及存储原件在结束时清理。

没有付费模型调用，没有积累真实律师标注样本，没有训练/微调，也未重新测定真实生成通过率。下一步实际运营工作是让律师围绕少量有代表性的修改形成样本，再用同一留出集检查后续改动是否改善质量。
