# 第五轮：自然问答、核验分流与诉求落实

本轮完成上一轮审阅建议中优先的三项。沿用 Node + Pi SDK、后台任务和同一位负责律师；没有增加固定模型阶段，也没有新增退回、换律师或审批流程。交易规则统一更新到平台 Skill 5.5.0。

## 用户可见行为

- 解释条款、咨询和讨论假设可直接回答。成功回答后保留原交易摘要、确认时间和已生成版本，不要求重新确认或生成。实际补充、更正、修改仍走原有摘要确认和局部修改流程。
- 问答使用当前最新已保存的合同正文作为依据；没有正文时明确说明。只读问题不会被拼进下一次局部修改的请求。
- 确切事实冲突继续定位修复。事实无法核对时保留候选稿、说明缺口，停止自动改写；用户可补充信息或手动重试。法律专业不确定性随初稿留给原负责律师，并明确标记尚待律师判断。
- 生成结果新增“本版起草说明”：核心诉求、落实程度、条款原文落点以及律师待核事项。客户起草页、律师送审版本侧栏和完成消息均可看到。说明不写进合同正文。
- 用户没有表达核心诉求时不强制询问；表达过但本轮未能评估时明确显示未评估，不声称已落实。部分落实或未落实的诉求不会成为新的生成门槛。

## 实现边界

1. `update_contract_spec` 在同一次调用中选择 `answer` 或 `update`。只读分支不接受事实、参与方或诉求更新字段；业务判断仍归统一 Skill。
2. 意图处理期间保留输入版本占位及原确认快照。只读成功仅恢复自己的占位，不能覆盖后续材料变化或更早未处理的变更。取消及过期执行受原有任务租约保护。
3. 在生成失败后询问问题，保留原候选稿与重试入口。手动重试使用新的执行编号，避免 Pi 缓存反复返回同一个不确定结论；进程恢复仍可复用已完成阶段。内部候选稿不进入浏览器详情或进度快照。
4. `FACT_CHECK_UNCERTAIN` 与 `DRAFT_MISMATCH` 分开。前者不自动进入重写；后者保留原有有限修复预算。未分类的旧 `uncertain` 结果保守归为事实待核。
5. `agentOutcome` 绑定本版正文哈希和确认记录中的诉求。条款引用须能在指定正文或附件中逐字定位；声称已有条款回应时必须有落点。修改后清除旧结论，再对新版检查。核验模型的意见不等于律师审定或法律有效性证明。

## 验证

本地验证使用合成交易、模型替身和隔离数据库；未运行付费模型或 100 用户生成测试。测试覆盖只读保留确认、问答与修改衔接、失败与取消、旧变更未处理、材料版本竞争、专业/事实不确定性、真实冲突、引用校验、诉求撤回、版本隔离及持久会话重试。

本次结果：

- 完整单元回归 273 项：260 通过，13 项数据库测试按默认配置跳过，0 失败；新增 17 项针对性测试。最后的工作流改动再运行相关 25 项，全部通过。
- 类型检查、Node 发布构建和独立 worker 构建通过。
- 使用临时数据库空间运行最终构建的 Node + 独立 worker + Pi 完整流程，11 次本地模型替身调用，通过问答后原版送审、专业待核初稿、律师读取诉求说明、沟通、保存及交付检查；测试空间已清理。
- 浏览器检查通过：律师侧栏显示诉求及条款原文；原有桌面/移动预览、历史读取和保存失败恢复正常。模拟的首次保存状态同步 503 为测试注入，无未处理页面错误。
- 未调用付费模型。测试与构建日志位于忽略目录 `.data/qa/agent-phase5-*`。

## 尚未包含

本轮没有增加 OCR、法律全文与效力核验、完整任务质量评估集或单任务 Token/费用预算。真实模型对意图和法律专业问题的判断效果仍需少量实际案例与律师反馈评估；本轮不能作为“真实合同任务通过率已达 95%”的证据。未部署或进行线上验收。
