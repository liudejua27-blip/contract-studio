# 复杂合同生成与阶段恢复改进

本轮目标：解决复杂任务在信息整理时被截断、原样重试、失败后丢失有效进度的问题。保留现有 Pi SDK、模型提供方、用户确认与律师完善流程。

## 实现

- 输出额度按阶段配置：整理/核验默认 16,384，起草/修改默认 24,576。明确检测 `finish_reason=length`，不解析或执行被截断的工具参数；增加额度并要求增量提交。达到恢复上限后停止自动调用，后台不再把截断误判为网络故障反复运行。
- 结果工具增加 `complete=false` 暂存。每次只提交新增或修正字段，`complete=true` 合并后运行原有完整结构、证据、数值、来源及导出校验。暂存内容仅为私有候选，不是已确认事实，也不能直接下载或送律师。
- 事实、事项判断、参与方按稳定 ID 合并；正文和附件支持按位置分段写入，重放同一位置不会重复追加；已有正文的少量修正若未指定位置且会缩短条款数组，会提示内部修正而不覆盖原内容。只读答案不继承暂存的事实修改。
- 每次暂存、校验反馈、输出策略调整及最终接受结果均保存到私有会话检查点。正式服务仍使用现有数据库检查点和任务租约校验。进程恢复从候选进度继续，不把不完整工具链重新发给模型。
- 新阶段使用当前事实台账和近期对话，历史原话仍可通过工具完整找回。各阶段只暴露相关提交参数和说明；核验阶段不提供正文位置参数。当前阶段压缩已物化的旧提交，保留最新工具调用与回执，保证对话能够继续推进。
- 事项判断支持 `evidenceFactIds`，由程序从已验证事实展开原话。已有判断随引用事实的日期/金额修改刷新证据，避免继续引用旧版本而误报缺项。
- 新任务默认 Token 处理上限从 500,000 放宽到 2,000,000，避免旧上限先于复杂流程恢复而中止任务；显式配置与已有任务的额度快照仍然有效。
- 人工重试会重新做需要重评的已完成核验，同时复用未完成的候选进度；新用户请求、材料变化或不同合同不会复用旧候选。

## 验证方法

1. 确定性测试覆盖截断后请求变化、上限停止、后台不重复重试、跨私有目录恢复、未改字段保留、重复分段幂等、错误修正、候选隔离、证据随日期更新。
2. 使用上一轮冻结的三个合成复杂案例，真实调用配置模型，执行资料整理、确认、生成 Word、只读问答、局部修改和再次导出。
3. 真实复测暂时放宽任务用量和时间上限，以隔离生成与恢复问题；没有改用户本地凭据或在线配置，没有把这些测试当作默认预算容量证明。
4. 恢复测试读取被停止测试进程留下的合同、材料 ID 和私有会话，在新目录恢复。测试存储模拟已停止执行者的租约回收，不等同于生产 PostgreSQL、服务器故障切换验收。
