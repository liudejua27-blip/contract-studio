# 后台生成与断线恢复（本地 Node 版）

本次范围：离开页面继续生成、回来恢复进度、临时故障有限重试。保留完整 Pi SDK、通用起草与按需专项 Skill、Word 初稿和律师审核流程；未部署。

## 实现

- `src/instrumentation.ts` 随长期运行的 Node 服务启动任务扫描器。无需另一个任务平台或 Cloudflare Queue，默认最多同时处理两份合同，每秒检查可执行任务。
- 继续以 PostgreSQL 中的 `contracts.workflow` 为任务记录。先通过现有版本号比较保存执行租约，再调用模型。同一合同并发领取只有一次成功；完成结果必须仍拥有当前租约才可保存。
- 新任务标记 `execution: background`。浏览器订阅 `GET /api/contracts/:id/jobs/:jobId/events`，不推进生成阶段。旧 Node `/run` 接口兼容为订阅；Sites 兼容构建仍保留原执行方式。
- 公共阶段状态和正文预览合并后写入 `contracts.agent_progress`，与业务版本号分开，每 200ms 至多排入一次保存；每次保存核对任务与租约。该字段不存模型隐藏推理。
- 订阅每 500ms 读取已保存状态，约 25 秒轮换连接。重连先恢复完整预览，再传增量，避免重复追加。采用最新快照恢复，不是逐条历史事件重放。
- 浏览器断线只关闭订阅。重连由原有 5 秒恢复轮询重新触发；明确点击停止才取消后台任务。停止和新任务的租约校验继续防止旧结果写回。
- 临时模型故障、超时、空响应和可识别的临时存储故障，每阶段最多追加两次后台重试，等待 2/4 秒。SDK 内已有的单次请求恢复仍保留。配置与权限错误不自动重试，业务事实缺失仍等待用户回答。
- Word 保存重试保留已核对合同内容，只重新导出；不重新询问或调用起草模型。
- 服务退出留下的运行任务，租约过期后自动接管，单任务最多两次。当前租约为模型阶段预算加 60 秒（默认约 5 分钟），因此进程崩溃恢复有等待窗口，不承诺瞬间恢复。
- Pi 会话文件锁每 5 秒更新，30 秒未更新可过期。避免死进程的会话锁比任务租约存活更久。短时会话锁竞争等待 20/40 秒后有限重试；活跃任务仍由数据库租约约束。

## 运行与数据

仍通过 `npm run dev` 或构建后的 `npm start` 启动现有 Node 应用，后台循环自动启动。数据库初始化增加 `agent_progress` 字段与活动任务索引；本地数据库已补齐这两项。新数据库先执行 `npm run db:init`。

Node 进程必须保持运行，`CONTRACT_PI_SESSION_DIR` 必须持久化，文件存储仍使用已有适配器。这不是面向随时回收进程的纯短请求部署方案。现有 Sites 线上网站未因此自动切换或更新。

## 验证

- 新增后台恢复测试：无浏览器导出、重试退避与上限、重启租约回收、并发领取、断线恢复、预览保存、拒绝错误凭据的重试等。
- `scripts/background-recovery-smoke.ts` 使用独立 PostgreSQL schema、真实生产构建 Node 服务、完整 Pi SDK、合成 SSE 模型与本地存储协议模拟。运行结束清理数据库测试数据，不读取或调用真实客户合同。
- 全链路检查包含：503 恢复、无订阅完成任务、预览后断开仍完成 Word、重复提交只有一个版本、无登录无法订阅、服务重启从导出检查点完成、强制杀死正在起草的进程后等待真实租约过期再完成。
- 浏览器通过 Playwright CLI 实际操作：输入合成采购需求、确认起草、刷新页面、观察原任务生成并出现下载入口。截图在 `output/playwright/background-restored-word.png`。

这些验证针对运行可靠性。合成模型输出不是合同质量样本；没有在本轮进行真实模型质量评估、律师审查或线上部署验收。
