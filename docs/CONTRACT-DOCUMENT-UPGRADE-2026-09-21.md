# 合同文档与事实完整性升级

本轮仅完成本地实现和验证，未部署到 Sites。A4、小四、1.5 倍行距是本产品排版规范，不表示所有合同具有统一法定版式。

## 实现

- 主体支持企业、个人和 2–20 方，参与方与已确认事实对应；新增结构化地址、联系方式、登记信息和签署代表，不伪造未知信息。
- 用户与律师界面显示签署资料核对清单。客户可先下载和送审，补充资料通过现有对话生成新确认，不直接修改已保存或已送审版本。
- Word 使用 A4、2.54 cm 页边距、宋体 12 pt、正文 1.5 倍行距、连续条号、页眉和“当前页／总页数”。独立签署页区分个人签名与组织签署区域，签署日期留给实际签署时填写。
- 正文和附件支持段落、下级标题、列表及真实 Word 表格；表格跨页重复表头，附件可有独立确认区。保留既有纯文本合同读取能力。
- 表格、附件、签署说明纳入内容核对和版本摘要。增加结构化正文一致性、主体依据及表格金额检查（包括金额单位只在表头的情况）。
- 分成交易关注收款、结算支付路径、退款和折扣口径；专业事项与暂未确定事实继续进入律师待审记录。用户答案分布在其他事实字段时不因专用字段为空而重复询问。
- 更新平台 `contract-word` Skill；通用交易起草方式与中国法律 Skills 保持不变。网页预览允许流式呈现结构化正文文本，内部审查记录不进入公开预览。

## 本地验证

- 自动测试：116 项，112 通过、4 跳过、0 失败。跳过项是原有数据库集成场景；不视为通过。
- Node 生产构建、Sites 构建与 Sites 类型检查通过。没有执行部署。
- 六类合成排版样本：企业双方、企业与个人、三方、无偿服务、设备分成、45 行跨页表格。实际调用生产 Word 生成器，再用独立 LibreOffice 渲染，共 26 页；检查中文字体、A4、签署留白、页码及跨页表头。样本用于排版测试，不代表合同内容已经律师认可。
- 真实配置模型 + 完整 Pi SDK：咖啡机、点单软件和门店分成交易完成事实整理、起草、一致性检查、DOCX 生成。耗时 77,988 ms，55 次草稿预览事件；3 条规则应用均定位到正文，13 条 Skill 读取记录。Word 渲染为 3 页，已检查。
- 首次真实测试发现模型将运营答案存入 scope 后仍被规则重复询问；已修复跨字段识别并增加独立回归测试。修复后同一案例没有缺失事项。
- 桌面和 390 px 手机网页已验证签署资料表单可将填写内容发入对话，原版本保持不变，手机页面没有横向溢出。浏览器测试使用本地模拟接口，不是线上服务验收。
