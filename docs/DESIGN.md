# Design baseline
Visual target: docs/client-concept.png and lawyer-concept.png generated from approved written scope. This is the working implementation baseline, not a claim of explicit user image approval.
Pure-white content, neutral #f0f2f3 sidebar/canvas, #245849 primary accent, #18211e ink, #67726e muted, #dfe3e1 borders. Chinese system sans UI, Song serif document. No imagery needed for application chrome. 248px desktop navigation, 72px header, conversation 40% and document 60%. Lawyer review wide document / narrow 320px context. Tablet rail collapses, mobile full-width conversation/document switch.
Components: flat rail navigation, compact toolbar, paper canvas, message bubbles, inset composer, flat task table, focus-visible form controls, dialog. Button radius 6px, message radius 8px, composer 8px. 14px UI text/22px line height; 24px main section titles; document typography supplied by generated DOCX.
Copy permitted: 合同工作室 / 新建合同 / 我的合同 / 最近合同 / 合同起草 / 合同预览 / 下载Word / 提交律师审核 / 审核待办 / 已完成 / 用户需求 / 审核记录 / 与用户沟通 / 交付说明 / 确认交付. Additional required functional surfaces: login/register, admin accounts+assignment, error notices, version selector, capability notice and explicit demo-mode labeling, unavailable-editor fallback, empty states, supplemental messages.
Concept sample legal content is illustrative only. Never seed it as real user facts or assume arbitrary payment ratios. Real actual DOCX is rendered using docx-preview, not a mock paper UI. Production ONLYOFFICE chrome differs from concept's schematic toolbar; retain real editor controls.
Interaction: keyboard-submit composer (Shift+Enter newline), progress and failures, drafts preserved on failure, immutable document versions, explicit frozen-version review submission, exact saved review version delivery. No automatic contact outside app.
