# 通用回退与局部修改（2026-09-22，本地）

本轮在现有 Pi SDK 会话和工具循环上修改，默认仍为 Flash / high。没有增加第二个 Agent、法律检索服务或新部署。线上 Sites 尚未更新。

## 本轮变化

1. **模型判断意思，程序核对依据。** 移除 businessChecks 中以“不知道”等关键词否定 answered、强制 missing 转 deferred 的规则。用户不知道法律措辞，不等于没有决定付款。暂未决定也可以用“等合伙人拍板”表达。保留事实原文、金额、结构、明确未定来源的检查；这不是无条件信任模型。
2. **类型只帮助查参考。** templateId 为 null、未提供或没有登记时统一使用 general，继续同一套交易检查，保留已有事实与律师事项。不再因为模板未命中直接拒绝。但主体、交换、履行等实质缺口仍须处理。
3. **现代起草方案服从事项判断。** 不再仅因原话含“没有销售分成”就加入分成模块；旧冻结数据仍保留原兼容行为。
4. **原稿局部修改。** apply_contract_patch 绑定原稿内容指纹，按原数组位置替换、删除或追加正文、附件，必要时修改标题、主体与签署说明。不接受过期指纹、不存在的位置、同位置重复修改或整份合同冒充补丁。未涉及部分直接保留，不重新让模型抄写。
5. **统一修改路径。** 已有结构化初稿的用户修改，以及一致性检查失败的自动修复，都沿用该工具。初次起草仍生成全文。核对失败最多自动修复两次；没有通过核对不能发布 Word。文件保存失败继续从已有内容恢复，不重新起草。
6. **修改后全稿复核。** 重新验证金额、结构、事实覆盖及语义一致性，重建规则关联指纹。原版本不变，旧版审查事项保留，新版独立保存与送审。
7. **修改也流式显示。** 前端继续使用已有流式链路；新增补丁正文和表格的公开预览，不显示指纹、修改理由、规则引用等内部工具数据。

## Skill 4.3.0

通用起草 Skill 明确：未知类型继续起草；已明确事实不受“不懂法律”影响；仅对重要交易缺口追问。已知用途的成果以既有目的使用、第三方权利等普通规则衔接，不让用户选择著作权法律归属，也不默认转让。标准 ip 规则可被实际保留与使用。

对设备交接、标识和假设风险，区分“必须先决定的本次交易”与“履行时核对／普通责任条款”；不为所有未来意外逐项问卷。咖啡品类等可能影响交换义务的细节仍可以简短询问。

## 验证边界

- 自动化用例检查执行与来源约束；不以模拟模型证明语义判断正确。
- 真实 Flash high 对话报告和真实 Word 修订交付结果补充在下方。
- 本地 HTTP 验收使用隔离数据库 schema、合成企业与律师账号、本地文件存储；结束清理 schema。律师可读取同一个 Word 文件不等于真人律师已经审查法律质量。
- 本轮没有浏览器视觉验收、部署或线上验收。通用模型仍可能出现额外追问，不能由少量样本宣称任意交易稳定达标。
