# 对话追问与空响应恢复

- 通知联系方式不再作为所有合同的统一生成门槛；用户提供时保留。
- 缺少验收、违约或争议处理时，提供单独标注的建议，用户确认摘要后才并入事实用于生成。撤回某项约定时不直接拿建议顶替。金额、税费、发票、付款安排、期限和权利归属仍需明确。
- 保留未修改的已知信息，支持模型明确清除已撤回或变为未知的字段；最新明确修改不视为冲突。每轮最多询问两个缺项。
- 模型空响应或短暂连接失败最多自动恢复一次，总预算仍为65秒；空JSON响应恢复时切换为文本模式要求JSON，随后仍通过原有结构、事实和导出校验。不会把推理内容当作合同回答。仅记录回答类型、结束原因、数量，不记录原文或密钥。
- 两次失败后保留消息和旧摘要，旧摘要无法越过新需求确认门槛。

验证：自动测试新增恢复上限、保留事实/明确撤回、建议确认边界；真实DeepSeek三轮测试（三期30/40/30→两期未定→恢复最初三期）通过，恢复后金额及节点完整、无重复缺项。验收、违约和争议处理仍为待用户确认建议。

参考：DeepSeek官方JSON模式文档说明可能返回空content：https://api-docs.deepseek.com/zh-cn/guides/json_mode/ 。本次诊断不能证明每一次历史空响应都有同一个服务端原因。
