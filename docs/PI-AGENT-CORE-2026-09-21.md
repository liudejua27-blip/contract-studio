# Pi Agent Core 改造与本地验收

日期：2026-09-21。状态：本地实现及验证完成，未部署线上。客户可在律师审核前下载 AI 初稿，律师确认的交付版仍单独保存。

## 产品行为

- 用户负责说明交易，Agent 负责整理和起草，律师负责最终审核。每轮最多三个普通话问题，只补齐会影响合同的事实。
- 主体、事项、金额、付款、时间、交付物属于交易事实。软件、采购、服务使用各自的事实字段，不向用户询问管辖、法律适用、可分割性等专业判断。
- 专业默认条款与用户事实分别保存；律师工作台能查看默认内容、待审提示和用户撤回的约定。默认规则仍须律师专业审定。
- 用户不确定付款安排时，可接受系统提供的具体生意建议；采纳记录包含来源和证据。未接受的建议不变成事实，也不凭空补出主体或价格。
- 修改约定会替换旧事实；明确表示未定会清除旧值。确认摘要只列交易约定，不能把默认法律条款伪装成用户指示。
- 初稿下载显示“未经律师审核”；普通律师消息不再自动转成“待补充”，律师主动选择请求补充时才改变审核状态。

## 运行结构

`@earendil-works/pi-agent-core` 与 `@earendil-works/pi-ai` 固定为 0.86.1。没有引入独立 Node Agent 服务，也没有另建 OpenAI Agents SDK 运行时。现有 Next.js 服务端与 Cloudflare Worker 共用 Agent 和业务工作流。

`src/server/agent/runtime.ts` 使用真正的 Pi Agent 工具循环，模型传输适配现有 DeepSeek 的兼容接口，采用非流式文本及工具响应。最多四轮，每阶段共享 65 秒截止时间，传输空响应或连接故障最多重试一次；不向前端暴露模型内部推理或原始服务商错误。

理解、生成、核对分别提交结构化结果；规则查询是只读工具。提交工具先进行结构和业务校验，失败反馈给模型纠正。工具只暂存结果，最终写入仍走现有业务工作流和版本控制。兼容直接 JSON 输出时也执行相同校验。内容核对不一致最多自动重写两次，仍失败则停止，不导出未经核对的版本。

工作流持久化阶段结果，而非保存可无限重放的完整 Pi 对话。阶段中断后可能重新执行纯模型请求，但不会由工具直接发消息、创建审核或重复交付文件。

## Sites 运行方式（按用户要求更新）

已删除可选 Queue 接入、消费者、定时补偿和队列构建配置。仅使用 Sites，页面通过 HTTP 推进已持久化的任务阶段；保留幂等、租约、取消与重试。生成期间需保持页面打开。无需用户配置独立 Cloudflare 账户。下方 Queue 测试为删除前的历史证据，不代表当前功能。

| 检查 | 结果与范围 |
| --- | --- |
| 自动测试 | 55 项：51 通过、4 项数据库环境相关测试跳过、0 失败；最后的未定付款清除改动另外通过全部 6 项 Pi 专项测试 |

| 现有 Worker 回归 | 角色隔离、下载字节、送审冻结、分配/转交、禁用账户、跨用户访问与相关流程通过 |
| Pi + workerd + Queue | 模拟模型验证工具调用、无浏览器推进、重复确认只生成一版、取消后不提交、律师审核前下载 |
| 真实模型 + Worker | DeepSeek `deepseek-v4-pro` 经 workerd 和 Queue 完成采购理解、生成、核对、Word 下载；4 次模型调用，重复确认只生成一版 |
| 真实模型业务变更 | 软件交易生成 Word；三笔改两笔且比例未定时清除旧付款，接受建议后补齐，无重复追问 |
| 浏览器 | 本地 Chrome 桌面/手机检查摘要确认、初稿下载、建议采纳；律师端默认规则显示、普通沟通与请求补充分别验证。浏览器使用模拟模型，真实模型链路另测 |

新回归报告保存于忽略的 `.data/cloud-smoke-results.json`、`.data/pi-worker-smoke.json`、`.data/pi-worker-live.json`。测试合同均为合成数据，凭据不写入报告。可复现命令：

```sh
npm run typecheck

npm test
npm run build
node --import tsx scripts/cloud-smoke.mjs
node --import tsx scripts/pi-worker-smoke.mjs
# 使用本机已有模型配置，会产生模型调用费用：
CONTRACT_PI_LIVE=1 node --env-file=.env.local --import tsx scripts/pi-worker-smoke.mjs

```
