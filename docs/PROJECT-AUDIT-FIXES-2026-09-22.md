# 项目审查修复：本地实现与验证

日期：2026-09-22。范围为本地代码、隔离数据库和合成交易；未部署 Sites 或 Node 服务，没有联系真人律师。

## 已处理的问题

| 问题 | 本次行为 |
| --- | --- |
| 一部分安排未定导致整个事实被删除 | 同一事项可同时保存已知 facts 和 deferred 状态；重要未定项仍阻止确认，但不重复追问。明确撤回由 clearedFields 处理。通用起草 Skill 更新为 4.3.1。 |
| 过期或缺失的 Word 能送审 | Node 与 Sites 使用共同版本政策。初稿必须对应当前确认摘要和输入版本；实际读取文件并核对 SHA-256 后才接受送审。旧版仍可下载，但需要生成包含最新约定的新版才能送审。 |
| 律师修改被 AI 从旧需求重新起草覆盖 | 最新文件来自律师时，禁止进入 AI 起草/重试；客户修改意见以该律师 Word 为基础交回律师，保留所有已有版本。 |
| 多轮审核默认打开旧任务 | 根据状态与提交时间选择当前任务，不再依赖数组存储顺序；有活动任务的合同不再同时进入已完成列表。 |
| 重要未定事项缺少律师入口 | 新增“请律师协助确认未定约定”。无 Word 的协助不称为合同审核，不冻结起草，不允许上传交付版。律师建议须由客户主动采用后才成为起草输入。生成 Word 后将原沟通升级为正式审核，保留消息。 |
| 律师尚未接单时客户不能补充信息 | 客户可在等待状态发消息，状态保持等待；律师先接收任务再处理。 |
| 局部修改的工具输出不显示 | 把 apply_contract_patch 纳入模型流的公开正文入口，仍过滤内部理由、哈希与事实证据。 |
| 停止/失败后旧 Word 被空白预览遮住 | 只有 pending/running 使用实时文档区域；失败或停止仍显示已保存 Word、版本选择和恢复提示。 |
| 切换合同会丢失未发送输入 | 新合同与各合同的输入按账户隔离保存在当前浏览器标签页，切换或刷新保留，发送成功才清除，退出账户清除。发送失败保持原文。 |
| 客户看到内部模板和字段说明 | 文档区展示合同初稿、版本和签署资料；Skill 技术核对留在律师/管理端；自动生成的确认消息显示简短确认文案，交易摘要仍可查阅。 |
| 进度和列表反复加载完整合同 | Node 进度订阅每轮只查任务和公开预览，结束时取完整合同；会话有效性检查改成轻量查询；列表查询不读取聊天正文和 Word 内容，审核信息批量获取；保存消息/版本改为批量插入。 |
| Node 没有用户生成限制 | 默认每账户同时 1 个活动任务、每小时 40 次起草请求。用户级数据库锁、配额和任务写入在同一事务内；重复请求与自动阶段切换不额外计数，拒绝后回滚计数。可通过环境变量调整。 |

## 仍然保留的边界

- 不自动解析并修改律师上传的任意 Word；此类后续修改交给律师处理，防止丢失律师条款。AI 对自身结构化初稿仍支持局部修改。
- 真实律师的专业审定、生产部署、线上网络恢复和多用户负载验收尚未进行。
- 本轮简化的是现有 Node/Pi 路径，没有增加 Queue、第二套 Agent、RAG 或新的模型提供方。Sites 兼容代码同步了送审与沟通行为，但不等于 Sites 线上已升级为 Node SDK 服务。
