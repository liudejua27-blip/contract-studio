# Node 服务器运行与维护

本仓库只发布 Node 服务器版，`npm run build` 同时生成 Next.js 应用和 `.worker-build` 后台/维护程序。Sites、D1、R2 适配、Worker 运行时、副构建和专用检查已删除。历史审计文档保留历史结论，不代表当前发布入口。

## 发布前与首次启动

要求 Node 22.13 或更新的受支持版本、PostgreSQL、私有 S3/MinIO、HTTPS 反向代理。备份机另需与数据库服务器相同主版本（或兼容的较新版本）的 `pg_dump` / `pg_restore`；可用 `CONTRACT_PG_BIN_DIR` 指定目录。

1. 构建环境执行 `npm ci`。在隔离验收数据库的 `.env.local` 中配置 `DATABASE_URL`，运行 `npm run check:release`。此检查构建真实 Node 产物，启动独立 worker，使用本地模型及对象存储替身验证生成、审核、交付、安全限制；不访问真实模型、不做 100 用户压测。要求有创建临时 schema 的权限。
2. 将 `.next-build`、`.worker-build`、`public`、`next.config.mjs`、`package.json`、锁文件与生产依赖部署到同一个版本目录。`npm ci --omit=dev` 安装运行依赖，所有进程必须使用相同版本。也可以保留完整仓库，但不能公开 `.data` 或环境文件。
3. 将受控环境文件注入运行进程。生产至少配置 `NODE_ENV=production`、HTTPS 的 `APP_BASE_URL`、长度不少于 32 的随机 `CONTRACT_SESSION_SECRET`、数据库、私有对象存储、模型和 `CONTRACT_WORKER_MODE=external`。不要复用示例密钥。密钥不写入前端构建变量。
4. 升级已有实例前停止旧网页和 worker，先备份。执行 `npm run db:migrate`，然后 `npm run admin:bootstrap`（仅第一次部署，需 `CONTRACT_BOOTSTRAP_ADMIN_EMAIL`）。初始密码只写入权限 0600 的 `.data/bootstrap-admin.json`，交付管理员后移除该文件。初次登录必须改密。升级时已有管理员也会被要求改密一次。
5. 启动 `npm run start` 和 `npm run workers:autoscale`。`ops/systemd` 提供网页、worker、监控及备份定时器模板，需安装时调整用户、路径和环境文件。没有自动安装或启动任何服务器服务。
6. Node 端口只监听本机；按 `ops/nginx.conf.example` 配置反向代理、HTTPS、30 MB 入口限制与流式响应。只有代理覆盖来源头且 Node 无公开直连入口时，才设 `CONTRACT_TRUST_PROXY=true`。代理日志使用不含查询字符串的 `$uri`，不要记录 ONLYOFFICE 签名链接。

数据库初始化是幂等迁移。数据库和对象存储要持久保存；迁移账户拥有 DDL 权限，日常网页/worker 账户只需业务表读写、序列及函数权限。访问审计只需追加/查询；维护账户另有清理权限。环境切换、备份迁移和邮件配置均由部署者完成。

## 账号与邮件

- 所有账户可在“账户安全”修改密码，修改后注销全部网站登录会话，未用重置链接作废。
- 管理员新建的账户需首次改密。忘记密码可由管理员核实身份后签发 30 分钟有效的一次性链接；签发要再次输入管理员密码，并立即注销该用户全部网站会话。链接只显示一次，不能贴到公共日志或工单。
- 配置 `CONTRACT_SMTP_HOST/PORT/SECURE/USER/PASSWORD`、`CONTRACT_MAIL_FROM` 后，用户可自助请求重置邮件和验证邮箱。生产 SMTP 必须使用证书校验通过的 TLS/STARTTLS。数据库只存令牌哈希，链接通过 URL fragment 传递，浏览器读到后删除。设置 `CONTRACT_REQUIRE_VERIFIED_EMAIL=true` 可要求邮箱验证后使用业务功能；启用前必须先验证邮件投递配置。
- SMTP 接入依据 [Nodemailer SMTP 配置](https://nodemailer.com/smtp)。代码与本地令牌流程已接入；本次没有向任何外部收件人发信，真实投递仍需在部署环境验收。
- 浏览器待重试消息和输入草稿保存在按账号隔离的 `sessionStorage`，有效期 30 分钟。退出、会话失效和跨标签页退出时清理，同时清除旧版 `localStorage` 遗留原文。

## 备份与恢复

`npm run ops:backup -- create /private/backups/unique-name` 创建包含数据库、所有引用 Word、合同材料原件、编辑器已保存版本以及 Pi 检查点/旧会话的备份。支持在线备份：数据库与文件引用使用同一个 PostgreSQL 导出快照；正在编辑的可变临时文件从该快照对应的不可变保存版本重建。用户尚未保存的编辑不属于备份内容。原理见 [pg_dump --snapshot](https://www.postgresql.org/docs/current/app-pgdump.html)。

`npm run ops:backup -- verify /private/backups/unique-name` 校验清单与文件 SHA-256。失败时没有完整清单的目录不能算成功备份。目录含合同和会话原文，必须保持私有，使用加密磁盘或加密备份仓库；不要放在网站目录或公共桶。

提供每天 02:00 的 systemd 备份定时器模板。创建 `/var/backups/contract-studio` 并赋予服务用户私有写权限后安装。另将完整备份复制到独立故障域并监控备份任务退出状态；仅有同机副本不能覆盖整机故障。建议保留每日 30 份、每月 12 份，按业务实际保留义务调整；代码不会擅自清理备份。

恢复步骤：

1. 停止所有网页、worker 和编辑器写入者，选择一份校验通过的备份。
2. 指向**全新空数据库、空私有桶/前缀、空 Pi 会话目录**；不要指向现有运行实例。
3. 执行 `npm run ops:backup -- restore /private/backups/unique-name --offline`。恢复工具拒绝覆盖现有数据库表、非空 schema 和非空文件存储；单事务恢复数据库，核验对象字节，并注销旧登录会话、重置/验证链接和执行租约。任一步失败都不要启动服务，重新准备空目标后重做。
4. 轮换会话密钥与 ONLYOFFICE 签名密钥，重新打开编辑器，确认账户、合同版本、Word 下载和任务恢复后再放流量。恢复使用备份原 schema；自定义 schema 要在 `DATABASE_URL` 的 search_path 中保持一致。

从旧版本升级后，已保存的律师 Word 若缺少版本对比文字，可在备份后先运行 `npm run ops:backfill-review-text` 查看数量，再运行 `npm run ops:backfill-review-text -- --apply`。程序逐份核对文件哈希后提取文字；损坏或缺失文件只计入跳过数，不会用其他版本填充。新在线保存会自动记录对比文字。上线验收须用当前部署的真实 ONLYOFFICE 服务完成一次律师修改、保存确认、交付、客户下载与修改意见流程。

初始运行目标：RPO 24 小时、RTO 2 小时；这是运维目标，不是服务器实测承诺。仓库提供单合同本地恢复演练 `scripts/backup-smoke.ts`，需要临时建库权限，验证 Word、材料原件及记录、Pi、编辑器快照、登录失效和删除清理，不调用模型。上线后再按实际数据量记录恢复用时。备份配置、数据库角色、S3 访问策略和 TLS 证书不包含在数据备份中，需另行私密保存。

## 监控与消息

管理员“运行状态”和 `npm run ops:monitor` 输出排队、执行、24 小时模型调用失败率、输入/输出 token、费用估算、超时审核及待补充数量。可配置队列等待、失败比例及日费用阈值。模型没报告用量时记录“未知”，费用不能被当作零或真实账单；单价由运营方按实际币种配置，缓存折扣等以供应商账单为准。

监控返回 0 表示未触发阈值，2 表示告警，1 表示检查失败。systemd 模板每分钟运行；应把退出状态、`account_mail_delivery_failed`、`model_usage_record_failed`、`access_audit_completion_failed`、备份失败接入服务器告警系统。没有默认配置或发送外部告警。管理页可直接查看告警。

审核分配、请求补充及交付消息与业务变更在同一个数据库事务内保存，用户在“消息通知”查看和标记已读。网站访问受保护资源前追加访问审计，结束后记录 HTTP 结果；正文、密码、重置令牌和隐藏推理不进入审计。结果日志写入失败会留下开始记录并输出告警事件；SSE 的 HTTP 200 只表示订阅建立，不能当作任务成功。

## 数据保留和删除

合同及版本默认保留，不自动按年龄删除。所有者或管理员可申请删除已结束且没有进行中审核/生成的合同，30 天内可撤销；申请后有新的业务修改会暂缓清理，需重新核实。审核未完成时应先正常完成业务处理。

维护必须先备份，停止全部写入者（包含所有主机 worker、网页和编辑器），等待执行租约释放，再执行：

```sh
npm run ops:maintenance -- --offline
npm run ops:maintenance -- --offline --apply
```

第一条只列出孤立文件数量；第二条清理到期合同及其消息、版本、审核、共享会话，并删除对应旧本机会话。文件清理只处理 `contracts/` 命名空间，跳过引用中的文件及最近 7 天的对象；不清理其他前缀。备份和维护通过数据库锁互斥。不要手工绕过这些规则在备份中途清桶。

临时执行目录超过 1 天后可在离线维护时清理；认证计数保留 1 天、过期重置/验证链接 7 天、过期登录会话额外保留 30 天、模型调用及通知 90 天、访问审计 365 天。备份和 S3 历史版本独立保留：对有删除要求的合同，应同时记录其备份最终过期时间；启用 S3 versioning 时需配置非当前版本生命周期，删除标记不等于历史字节消失。保留期限应在正式运营前与平台政策一致。

## 证据边界

本地功能检查、恢复演练和构建不代表已经部署。100 用户是现有并发策略的设计目标，没有进行 100 用户压测，也没有真实模型费用验证。专业律师审定、真实 SMTP 投递、生产基础设施权限、外部告警接收、实际恢复时间和线上网络恢复仍需部署后分别验收。

## 材料与法律检索

材料上传需要本版本 `db:migrate` 创建的 `contract_materials` 表，原件沿用私有对象存储。网页和 worker 使用相同版本及依赖；PDF 解析依赖运行目录中的生产包。法律检索为可选 Tavily 接入，在网页和 worker 环境设置 `CONTRACT_LEGAL_SEARCH_API_KEY` 后重启。未配置时网站明确显示待配置，不能据此声称核验现行法律。格式、权限、费用与验收边界见 [第三轮说明](AGENT-PHASE3-2026-09-26.md)。

## 律师反馈与质量积累

本版本迁移增加 `review_learning`，保留版本引用及确认记录，随数据库备份和来源合同级联清理。客户确认个人偏好，管理员确认匿名评估样本；权限不能互相替代。`npm run eval:feedback` 默认只显示说明，只有显式 `--generate` 才调用模型；导出/评分不调用模型。导出的匿名样本和评估报告仍为私有运营数据，需独立管理保留期限。使用和验收边界见 [第四轮说明](AGENT-PHASE4-2026-09-26.md)。

## Agent 任务预算与材料识别

- `CONTRACT_TASK_MAX_TOKENS=500000`、`CONTRACT_TASK_MAX_MODEL_CALLS=36`、`CONTRACT_TASK_MAX_DURATION_MS=900000` 是每个后台任务的默认上限。一次确认后的起草、核验及修复共用同一份预算；每条新对话是单独任务。时间从首次领取任务开始，包含阶段间等待。已有任务保存自己的策略快照，改环境变量仅影响新任务；手动重试不清零。
- 模型调用前先持久化预留量，返回后按报告用量结算。没有用量、连接中断或进程退出时保守记账；无法保存用量时停止新调用。输入采用字节估计，非精确分词；预留不足时收紧输出额度或停止。本地预算不能保证供应商实际账单严格相等，也不计法律检索服务费用。
- 管理员运营页显示各合同当前最近任务的调用次数、记账 Token 和模型耗时；历史任务的总调用统计仍来自 `model_calls`。不新增无限增长的任务流水；要做长期逐任务费用审计仍需单独存储历史账本。
- 扫描 PDF 可在上传服务所在机器安装 Poppler 的 `pdftoppm`、Tesseract 及 `chi_sim`/`eng` 语言数据后设置 `CONTRACT_OCR_ENABLED=true`。可用两个 `*_BIN` 变量指定受控绝对路径。不安装或不启用时仍能读取文字层，并明确标注扫描页缺失。
- OCR 仅处理没有文字层的页面，默认最多 5 页/45 秒，每个网页进程同时 1 份；硬上限 10 页/60 秒。临时原件和图片在结束后清理；外部进程通过参数数组调用，不执行文件中的指令。OCR 结果仍标记待核对，有文字层页面内的图片、复杂表格和附件不保证完整识别。首次部署须用实际扫描文件验收识别质量和 CPU/内存占用。材料上传等待上限为 120 秒，覆盖文字层读取及 OCR；旧材料不会因开启 OCR 自动改变，需在允许调整起草材料时移出后重新上传。
- 法律网页扩展沿用 `CONTRACT_LEGAL_SEARCH_API_KEY`，通过 Tavily 提取已经检索到的官方网址，分页读取；不将合同文件发送给检索服务。配置该服务也不代表自动核验法规效力。
