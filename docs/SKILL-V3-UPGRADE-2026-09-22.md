# 通用合同 Skill 3.0 升级

保留完整 Pi SDK 和现有工作流；仅本地实现、测试，没有部署。

## Skill 与程序的分工

- `transaction-contract` 3.0：理解参与方、投入和取得、钱款路径、交付及退出；从全部已有信息判断是否需要追问。通过 `businessChecks` 返回 answered、missing、deferred 及原话依据。只有影响合同的商业缺口才向用户提问，专业法律判断继续交给默认规则和律师。
- `contract-word` 3.0：选择段落、真实表格和实际附件，逐方保留主体和签署资料，通过平台生成、保存文件后交付。明确结构检查不等于视觉验收或律师审核。
- 两个 Skill 通过现有打包和阶段注入进入 Pi。版本读取记录标明 3.0.0；不新增另一套 Agent，不接外部数据库。

## 必要的程序改动

1. 主体资料按参与方限定依据，拒绝甲乙方邮箱、地址、代表人及签署要求串用；`details` 不能绕过检查。已经提供的标准主体字段不得直接省略。
2. 商业完整性判断有原话依据，模型的有效“已回答”决定优先于旧场景关键词；不得用未定原文标成已回答，也不得无用户依据直接转为暂未决定。
3. 修正退款规则：仅出现“退款”或“实收”不等于口径明确。明确未定的事项仍保存在律师待沟通记录，不编造答案或反复追问。回复与交易摘要明确列出未定事项，不再笼统声称信息已经齐全。
4. Word 下级标题使用真实多级编号，支持 1.1、1.1.1、1.2、1.2.1，各主条款独立编号；三级标题缺少父标题会被拦截。
