# 小微企业对话与事实处理升级

本次实施对应同日 `SMALL-BUSINESS-FLASH-HIGH-AUDIT-2026-09-22.md` 的实测问题。保持完整 Pi SDK、Flash Thinking high、通用起草与专项规则增强的架构；仅本地修改和验证，未部署。

## 实际修改

1. **口语事实不再要求重填格式。** 金额解释与原文证据分开，支持本次出现的“1800块”“3万”“价格改成4000”“一个月1200”“互不收钱/谁也不收钱”；区分按期、单价与总价。重复引用同一金额不再当作多个总价。金额、付款和日期的核对支持证据保存在其他字段的情况。保留付款合计、比例、日历日期检查，并对单一商品的明确数量与单价做算术核对；混合清单、折扣及复杂计价仍需语义核对。
2. **引用错误由 Agent 内部修复。** 原先只有通用合同族严格修复证据，专项合同可能丢掉事实并重新问用户；现在所有合同族统一在提交工具内部核对原话。公司名称也改为与最终保留的原文证据比对，避免拿模型简写对比全称导致无谓重试。无法修复时仍保留失败状态，不用伪造事实让流程通过。
3. **普通条款无需客户逐条确认。** 商业事项增加 `standard` 状态，只能引用已有的普通验收、补救、税费、发票、争议规则，并说明适用原因。它不进入用户事实，不产生新的金额、期限或授权；主体、价款、付款、交付、材料、分成等核心事实不能靠它跳过。
4. **收紧追问和建议。** 已有验收方式不再为了指定几日内验收而追问，已给付款节点不再为了添加几天期限而阻断。缺乏依据的默示验收建议、将月底付款延到次月的建议会退回 Agent 修复。用自定义字段包装违约金、发票类型、著作权归属等专业问题也会被拦回；需要了解设计用途时改问店招、包装、商标等实际用途。
5. **旧会话能重新评估旧缺项。** 对有完整业务判断的结果，上一轮缺项必须逐项重新判断；不能漏掉一个旧的多余问题，让它永久留在状态里。移除旧版总价格式诊断后，重新执行当前事实校验。仍保留真正未知的商业事项。
6. **对话更短，正文更正式。** 工具要求回复不超过180字，问题不超过100字，通常只用一句回应新内容；冲突时优先直接显示具体矛盾，避免先肯定一组互相矛盾的数字。Skill 4.1.0 区分口语沟通、原文证据和正式合同正文，要求正文及金额表把“1800块”规范成“1800元”，不改变数值与计价方式。
7. **评测不再只看选定最终字段。** 新增意外冲突、完整交易能否起草、具体算术矛盾和建议安全检查，保存逐轮交易快照，对改价和补充信息增加逐轮断言；保留原始评测报告，不覆写先前失败。

涉及 `src/server/ai.ts`、`src/lib/contract-library/fact-checks.ts`、`src/lib/business-checks.ts`、`src/lib/transaction-state.ts`、`src/lib/intake-guidance.ts`、`src/lib/standard-terms.ts` 和通用起草 Skill。Skill 已重新打包，版本记录为4.1.0。

## 代表性体验

纸杯采购完整描述后：简短确认已记下，显示摘要供确认，不增加付款天数、验收天数、违约金或发票类型的问题。

装修确实缺材料责任时：问“墙漆、地砖这些材料由哪方买，费用是含在3万里还是另算？”，保留已给价格和工期。

50把椅子、每把100、合计3000时：指出应为5000元，问是否有优惠或哪个金额需调整；不再要求用户使用特定金额格式。

## 验证边界

本次解决的是已复现的理解、追问及交付障碍，不等于所有行业交易都已覆盖，也没有真人律师法律质量评审。单次模型样本的通过率不代表长期稳定率。早一轮装修曾因多个内部校验重试耗时约157秒；后续已修复名称比对及无意义证据必填导致的重试，但不能据此宣称延迟问题完全解决。没有降低用户要求的 high 档位。

本轮确认了流式事件与本地后台任务相连；没有进行浏览器视觉验收，也没有改变线上部署状态。
