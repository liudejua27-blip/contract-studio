# 流式 Agent UI 本地升级记录

2026-09-21。已实现并完成本地验证，未部署线上。设计参考见 `STREAMING-AGENT-UI-DESIGN.md`。

## 已实现

- 继续使用现有 assistant-ui。流式回复进入同一会话消息，工作状态改为可展开的一行；移除会话外的大进度框与重复任务提示。
- 新增按合同订阅的内存展示 store，正文增量只通知对应会话和文档组件，避免每个增量更新 Studio 顶层状态。完成段落采用独立 memo 渲染。
- 服务端将累计预览转为增量，模型预览解析限频至约 80ms；去除 24,000 字符静默截断。按 JSON 结构路径选择公开正文，排除同名的内部 evidence / reviewNotes / 规则引用字段。
- 问答提示词改为优先输出简短的交易理解，再提交事实字段；后续追问仍由既有事实校验决定。无依据时允许不输出，不为展示编造内容。
- 工作流相邻阶段立即接续；轮询仅用于状态恢复，保留服务端租约和请求幂等。重试首次非空预览替换旧候选，不与旧正文拼接；阶段切换、失败和取消保留当前预览。
- 正文在桌面文档面板持续出现，移动端切换对话/合同；用户上滑时停止自动跟随。正文到达前只显示实际阶段，不制造假进度或事后逐字动画。
- 输入框在生成期间可编辑，服务端确认取消后才恢复发送。迟到流事件被连接令牌和已取消状态拒绝。登出时断开连接并清理本工作台的临时预览。
- 文件保存后显示版本卡片、下载和送审入口，生成中不提供未保存文件的下载。Word 加载期间保留已保存正文占位。律师提交仍使用原有版本和授权机制。
- 不新增前端依赖，不更换 Pi SDK、模型或 Word 引擎；现有 Node 和 Sites 兼容构建保持可构建。

- 流式相关测试：20 项通过。
- 全部现有测试加本次新增：104 项，100 项通过，4 项依赖环境的检查跳过。
- Node 构建、Sites 兼容构建、Node/Worker 类型检查通过。

- 浏览器验证覆盖超过 30,000 字符仍持续增长、上滑不被强制拉回、生成期间编辑、取消后文字保留及继续发送、390px 手机无横向溢出、真实 DOCX 渲染及送审弹窗绑定相同版本。

## 仍需区分的边界

- UI 不会消除真实模型的首字等待。模型没有公开内容时显示真实状态和计时；问答提示词已要求先输出简短 reply，但模型未遵循或没有可依据内容时，正式业务追问仍在事实整理完成后出现。没有将返回后的整段文字伪装成模型逐字输出。
- 新增展示 store 为页面内存。刷新能恢复服务端已保存的任务/正文，不能恢复尚未持久化的全部 token；未接入独立后台执行器，也不承诺关闭浏览器后继续推进所有阶段。
- 该实现保持原有阶段 POST/SSE 语义和连接令牌隔离，不提供跨刷新逐事件回放。临时网络中断先读取已保存结果，未能完成时保留预览并提示恢复。
- 浏览器验收使用模拟流，尚未测量生产网络的首字时间或到屏 P95；开发模式记录中仍有超过 50ms 的长任务，不能声称已经达到所有设备零卡顿。
- 此次没有改变合同事实规则、律师审核标准，也没有部署 Sites 或 Node 服务。
