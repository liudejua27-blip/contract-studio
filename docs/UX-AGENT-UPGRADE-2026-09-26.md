# Agent 与合同工作台升级记录

本次为 Node 项目的本地实现和验证，未部署。目标是让用户描述交易、Agent 形成可审阅初稿、律师围绕核心诉求完成审阅与交付。

## Agent 衔接与名称留空

- 需求理解、起草和核验使用同一份当前交易状态；明确传入的当前状态优先于历史上下文，缓存键包含该状态，避免重试恢复旧结果。起草和核验已有阶段事实，不再重复附加旧台账。
- 精简交易 Skill 的重复规则。合同专项工具先给范围索引，按需读取具体规则；需求理解获得专业默认条款全文，减少因只知道规则名称而多问问题。
- 参与方角色与主体名称分开处理。甲乙方名称允许为空，Word 的主体和签署位置显示填写横线，签署资料仍提示后续补齐；不编造名称。
- 空名称不再作为证据匹配的通配符，避免甲乙方地址、联系人等资料串用。金额、付款、工作范围等实质安排仍按原始事实处理。

## 交互与设计

参考 [Juro](https://juro.com/us) 的清晰标题层级、突出主操作和合同全流程表达，结合本项目中文工作台使用场景，采用暖白、深绿和低饱和侧栏。已先生成视觉概念，再对照实际页面检查。

| 区域 | 本次结果 |
| --- | --- |
| 新建合同 | 大标题、单一输入主入口、描述交易→形成 Word→律师审核三步提示 |
| Word 送审 | 原生模态对话框以“你的核心诉求是什么？”为主问题；立场快捷选择，律师安排折叠；提交失败在弹窗内反馈 |
| 律师右栏 | 诉求、沟通、版本、交付四个标签；支持键盘切换与侧栏加宽；事实和辅助信息按需展开 |
| 沟通 | 消息区独立滚动，输入区固定在下方 |
| 版本与交付 | 比较当前审核链的版本，默认只显示变更段落；展示保存及交付前置状态 |
| 窄屏 | 合同原文与审阅工作台切换；已观察 390 和 320 像素预览 |

视觉核对：桌面保留文档与工作台并排，移动端改为单视图切换；律师导航保留较深底色区分角色。概念图为设计参考，不是网站运行时图片。未新增外部图片或字体资源。

## 95% 评估目标

模型需求理解评估默认接受通过率至少 95%，可通过 `CONTRACT_EVAL_PASS_RATE` 调整。报告记录目标、通过率、所需通过数和是否达标；20 个场景允许 1 个失败。无场景不算通过，无效目标在调用模型前拒绝。

模型行为评估与确定性的权限、文件完整性和状态一致性检查分别执行。95% 是本次配置的验收目标，不代表已测得线上成功率。
