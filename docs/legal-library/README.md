## 运行与证据

用户显式选择的模板在用户消息中保留可读版本标记；现有 PostgreSQL 和 Sites D1 均使用相同选择规则。没有选择时只作有限别名推测；无法确定则明确未分类。新的选择优先于旧记录。

AI 每次调用接收该分类的必填问题、条款与风险关注点。生成完成后，服务器（不是模型）写入版本化 `content.drafting`：模板/规则版本、来源快照、检查时间和发现。外部模型返回的 drafting 字段不受信任。Word 文件与报告在同次版本保存中冻结。

自动检查是确定性的初筛，不是语义法律审查：
- 字段只定位用户明确标注的回答，自然语言未识别不直接认定缺失。
- 条款、风险定位正文，不因标题包含词语认定已包含条款。
- 找到相关原文标记 REVIEW（待复核）；未能判断、未定位或占位标记 UNKNOWN（待确认）。没有 PASS/合规分数。
- 原文片段与条款位置一同展示；没有凭空补证据。
- 律师上传的新文件不继承原稿的检查结果；UI 会提示没有本版检查记录，仍由律师审阅交付。

## 人工维护及限制

未覆盖劳动、借款、股权、建设工程、融资租赁、跨境及特殊行业交易。已有模板也须根据具体地区、事实与客户立场复核。模板的“必备”是产品起草清单，不是合同有效性的自动判定。

专业律师审定仍未完成。下一版应逐类由律师确认适用范围、调整条款、核实法律版本并留下真实审批记录。修改 catalog/engine 必须提升版本，新生成文件使用新版本；旧版本保存的报告和文件不回写。相关回归测试见 tests/contract-library.test.ts 与 scripts/cloud-smoke.mjs。
