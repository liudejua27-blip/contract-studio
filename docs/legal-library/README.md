## 已交付范围

12 类：中国大陆一般交易中的软件开发、服务合作、货物采购、保密协议、房屋租赁、设备租赁、设计委托、摄影摄像、营销推广、咨询服务、SaaS订阅、事务委托。

每类包含签署前需确认的信息、条款占位模板、风险复核清单、适用范围、参考依据、来源及固定版本。客户只描述合作：AI 先理解交易并自动选择参考，再起草 Word；只有影响交易方向的歧义才追问一个问题。普通姓名、日期、账户等空缺不阻止起草。客户页面不展示模板选择或逐项表单；律师、管理员可查阅参考库与空白 Word。库的状态统一为 `pending_lawyer_review`，没有虚构律师审批人或已审日期。

## 运行与证据

新客户端不传模板ID。服务器使用 DeepSeek 语义理解业务并从固定目录选择模板，同时判断直接起草、关键澄清或普通回答。分类结构经过校验，未知ID拒绝继续；目录外业务不硬套模板。最新澄清可以纠正旧分类，不因旧版本标记锁定。旧接口显式模板参数保留兼容；在新版客户UI没有该入口。生成决策由返回内容驱动，PostgreSQL与Sites D1均会保存AI主动起草的Word，不依赖用户额外点击“生成”。

AI 每次调用接收该分类的必填问题、条款与风险关注点。生成完成后，服务器（不是模型）写入版本化 `content.drafting`：模板/规则版本、来源快照、检查时间和发现。外部模型返回的 drafting 字段不受信任。Word 文件与报告在同次版本保存中冻结。

自动检查是确定性的初筛，不是语义法律审查：
- AI从自然描述提取字段原文，服务器核对字段是否属于模板、原文是否逐字存在于用户消息、是否包含未确认标记；伪造引文剔除。保留旧版明确标注回答的兼容定位。即使定位成功也只是待复核，不代表真实或已授权。
- 条款、风险定位正文，不因标题包含词语认定已包含条款。
- 找到相关原文标记 REVIEW（待复核）；未能判断、未定位或占位标记 UNKNOWN（待确认）。没有 PASS/合规分数。
- 原文片段与条款位置一同展示；没有凭空补证据。
- 律师上传的新文件不继承原稿的检查结果；UI 会提示没有本版检查记录，仍由律师审阅交付。

## 人工维护及限制

未覆盖劳动、借款、股权、建设工程、融资租赁、跨境及特殊行业交易。已有模板也须根据具体地区、事实与客户立场复核。模板的“必备”是产品起草清单，不是合同有效性的自动判定。

专业律师审定仍未完成。下一版应逐类由律师确认适用范围、调整条款、核实法律版本并留下真实审批记录。修改 catalog/engine 必须提升版本，新生成文件使用新版本；旧版本保存的报告和文件不回写。相关回归测试见 tests/contract-library.test.ts 与 scripts/cloud-smoke.mjs。

## 小微企业交互验收

自动匹配流程使用需求理解与起草两次模型调用，只有问清业务方向时可在第一步直接返回一个问题。额外调用存在延迟，未通过规则关键词假装语义理解。程序测试覆盖非术语描述、不传generate仍保存、最新澄清换类型、未覆盖类型、伪造事实证据和非法模板ID。
